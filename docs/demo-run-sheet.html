TAKE 10

Non-linear bonus — explain the code

Bonus · +10
This is the one part where the brief asks you to explain the code. Everywhere else you show the program working; here you also open the file.

Show samples/nl_circle.txt first and explain the format: the minnl keyword means the coefficients weight squares, so this is minimise x₁² + x₂² subject to x₁ + x₂ ≥ 4.

Keys 1›samples/nl_circle.txt› 2›6
Status: Optimal Objective: 8.000 x1 = 2.000 x2 = 2.000

“The nearest point on that line to the origin is (2,2), so 8 is right — you can check it in your head.”

Then open NonLinearSolver.cs and walk the three steps in the comment block: take the gradient, step along it, project back onto the feasible region. Emphasise the projection — there is no closed form for the nearest feasible point, but projecting onto one constraint at a time and cycling converges to their intersection.

Close with samples/nl_weighted.txt → 7.200 at (2.4, 0.6), which is what Lagrange multipliers give by hand.

4 vars samples/lp_max_4var.txt›113.846
5 constraints samples/lp_min_5con.txt›22.000

Five things that will bite on camera

  • Column prompts are 0-based; constraint prompts are 1-based. Options 1–4 and 7–8 ask for a grid column index, so x1 is 0. Options 5–6 ask for a constraint number, so the first constraint is 1. Mixing them up changes the wrong thing and the output looks wrong when it isn’t.
  • Options 1, 2, 7 and 8 error on lp_max. Both its decision variables are basic, so there is no valid non-basic input. Use lp_max_4var.txt for those four, as Take 08 does.
  • Demo minnl, not maxnl. Minimising a convex objective has one answer and the program reports it as global. Maximising one puts the optimum at a corner, so the program honestly reports a local optimum — accurate, but a confusing thing to explain on video.
  • The knapsack tableau is 143 characters wide. Widen the terminal before recording, or that section is unreadable and the marker cannot tick off the iterations they are supposed to see.
  • One error message still says “SolveResult is null”. It appears if you open sensitivity analysis before solving anything. Solve first and it never shows.
