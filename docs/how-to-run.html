Running the solver

Everything is on main and finished: five algorithms, the full sensitivity suite, duality, and the non-linear bonus. This is how to get it running on your machine, and the three things that will waste your afternoon if nobody tells you.

Start here

  1. Install the .NET 8 SDK

    winget install Microsoft.DotNet.SDK.8

    Then open a new terminal. The installer edits PATH and a shell that was already open will keep telling you dotnet is not recognised. Check it with dotnet --version — you want 8.0.x.

  2. Get on main

    git checkout main
git pull

    Do this before anything else

    The person-a, person-b and person-c branches are all well behind — 11, 8 and 19 commits respectively. If you branch from your old one you will be working against code that has since been fixed, and the merge will be painful. Branch from main.

  3. Build

    dotnet build -c Release

    Expect 0 Warning(s), 0 Error(s). Anything else means something is wrong on your machine, not in the repo — say so in the group chat rather than pushing a fix.

  4. Run it

    dotnet run --project src/solve/solve.csproj

    Or double-click the executable, which is the better option because the sample models are copied next to it and every path in the menu then just works:

    src\solve\bin\Release\net8.0\solve.exe

There are two executables

The marked one

solve.exe

The menu-driven console program the brief asks for. Load a model, pick an algorithm, run sensitivity analysis, write the output file. This is what the video demonstrates.

src\solve\bin\Release\net8.0\solve.exe

Optional

solve-gui.exe

A window over the same solvers, added to make recording easier. Same results — it calls the same code and shows the same text, you just click instead of type. Useful for the sensitivity section, where the console wants index numbers.

src\solve.gui\bin\Release\net8.0-windows\solve-gui.exe

Trying it in thirty seconds

From the console program, these keys load the classic max LP and solve it with the primal simplex. Menu choices are numbers; the file path is typed as shown.

1   load a model
    samples/lp_max.txt
2   choose an algorithm
1   primal simplex

    Status: Optimal
    Objective: 180.000

Then 4 writes the whole thing — canonical form, every tableau iteration, the result — to a text file you can open and read.

Three things that will trip you

  • Never call ToString or TryParse on a double without naming the culture. Our machines use a comma decimal separator. This has caused three separate bugs already: tableaus printing 4,000 instead of 4.000, and prompts rejecting 2.5 as “not a number”. Print through OutputWriter.Format(value), and parse with CultureInfo.InvariantCulture.
  • Grid columns are not the same as variables. A variable declared urs occupies two columns and one declared - is stored as its own negation, so column j is not variable j. Use CanonicalMatrix.RecoverOriginalValues(...) rather than reading the leading columns. Assuming otherwise works on every model that doesn’t use those two restrictions, then quietly returns wrong answers on the two that do.
  • Branch, don’t push to main. Both times work went straight to main it carried defects a review would have caught — eight between them. Work on a branch and merge, so somebody else sees it first.

There is more of this in the Contract details that are easy to get wrong section of the README. Read it before writing anything that touches a tableau.
